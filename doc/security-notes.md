# Заметки по безопасности и известные ограничения

## Rate limiting

Лимитер auth-методов (Register/Login/Refresh/Logout) ключуется по IP из
`peer.FromContext`. За reverse-proxy все клиенты приходят с адреса прокси и
делят один бюджет — под нагрузкой логин станет недоступен. Для деплоя за
прокси нужен ключ из `X-Forwarded-For` (с валидацией доверенного прокси) или
ключ по логину. Лимитер in-memory: при горизонтальном масштабировании
инстансы не разделяют счётчики.

## Refresh-токены

- Ротация атомарна: `DELETE ... WHERE id AND token_hash RETURNING` — из
  одного токена не может родиться две пары.
- Detection повторного использования уже ротированного токена (revoke всех
  сессий пользователя при replay) не реализован.
- Протухшие токены пользователя удаляются при его логине; токены
  пользователей, которые больше не логинятся, остаются — фоновой чистки нет.

## Прочее

- JWT без `iss`/`aud` — сервис один.
- Клиент ходит по insecure gRPC — TLS не включён.
- Пере-хеширование пароля при усилении параметров argon2 не реализовано;
  `Compare` читает параметры из хеша, база для миграции есть.

## Синхронизация

- Курсор синхронизации — серверный timestamp с отступом 5 секунд назад:
  конкурентная транзакция, закоммиченная после чтения, но с меткой раньше
  курсора, попадёт в следующий pull. Возможны дубли изменений — клиент
  дедуплицирует по (id, version). Строгое решение — монотонная
  последовательность вместо времени.
- Лимит gRPC-сообщения поднят до 64 МиБ с обеих сторон: это потолок
  ~60 секретов максимального размера в одном sync-батче. Больше — нужна
  пагинация изменений.

## Клиент

- Ключ шифрования хранится в session.json (0600) до logout — осознанный
  режим «stay logged in», чтобы не вводить мастер-пароль на каждую команду.
  Из ключа мастер-пароль не восстанавливается.
- Соль KDF детерминирована из логина (Bitwarden-модель): необходимо для
  синхронизации между устройствами без хранения соли на сервере. Плата —
  возможность пер-логин прекомпьютинга; смягчается memory-hard Argon2id.
- Логин нормализуется (нижний регистр, обрезка пробелов) идентично серверу
  до вывода ключей — регистр логина не влияет ни на вход, ни на расшифровку.
- Политика конфликтов синхронизации: сервер побеждает, локальная правка
  замещается серверной с предупреждением в выводе.
- Конкурентный доступ к vault.json и session.json сериализуется file-lock
  (flock); блокировка удерживается на время load-modify-save и refresh-ротации.
